# タダイマップ 外部インターフェース設計書

本アプリが連携する外部サービス・OS機能をまとめる。

## 1. Expo Push Notification Service（ネイティブアプリ向けプッシュ通知）

| 項目 | 内容 |
|---|---|
| 用途 | 状態変化の自動通知（F4）、手動でのステータス切替通知（F6・F12）。**ネイティブアプリ（Android/iOS）を利用中の端末のみ対象** |
| 連携方向 | APIサーバー → Expo Push Notification Service → 各端末 |
| 概要 | Android(Firebase Cloud Messaging)・iOS(Apple Push Notification service)の違いをExpoが吸収してくれるため、APIサーバーは1つの共通APIへリクエストするだけでよい |
| 送信データ例 | `{ "to": "ExponentPushToken[xxxx]", "title": "タダイマップ", "body": "お母さんが帰宅しました" }` |
| 認証情報 | Expoプロジェクトの設定のみで完結し、追加の秘密鍵は不要（Expo管理下のアプリの場合）。Android側はFirebase(FCM V1)のサービスアカウント鍵を別途`eas credentials`で登録する |
| 失敗時の扱い | 送信失敗はログに記録するのみとし、アプリの他機能には影響させない（状態更新・一覧表示は通知の成否に依存しない） |

## 2. Web Push（Web版向けプッシュ通知）

| 項目 | 内容 |
|---|---|
| 用途 | F15。ネイティブアプリを入れられない端末（Web版）向けの、状態変化のプッシュ通知 |
| 連携方向 | APIサーバー → 各ブラウザベンダーのPush配信サービス（Chrome/Safari等が内部的に利用するもの） → ブラウザ／Service Worker |
| 概要 | ブラウザ標準のPush API・VAPID仕様に準拠。サードパーティのサービス契約は不要で、自前で発行したVAPID鍵ペア（公開鍵・秘密鍵）とサーバー側の`web-push`ライブラリだけで完結する |
| 鍵の発行方法 | `node -e "console.log(JSON.stringify(require('web-push').generateVAPIDKeys()))"` で1回だけ生成し、`VAPID_PUBLIC_KEY`・`VAPID_PRIVATE_KEY`・`VAPID_SUBJECT`（連絡先`mailto:`）として環境変数に保存する |
| 送信データ例 | `webpush.sendNotification(subscription, JSON.stringify({ title: "タダイマップ", body: "お母さんが帰宅しました" }))` |
| 認証情報 | VAPID秘密鍵（`VAPID_PRIVATE_KEY`、必ず秘密情報として管理）。公開鍵は`GET /push/vapid-public-key`でブラウザに公開する前提の値 |
| 失敗時の扱い | 鍵の設定ミス（不正な形式等）を含め、送信処理全体を try/catch で保護し、状態更新エンドポイント自体は必ず`200 OK`を返す（Expo Push側と同じ方針） |
| 重要な制約 | iOS Safariでは、対象ページが「ホーム画面に追加」されたPWAとして開かれている場合のみPush APIが利用できる（iOS 16.4以降）。通常のタブでは購読自体が作成できない |

## 3. スマートフォンOSの位置情報機能（ジオフェンス）

| 項目 | 内容 |
|---|---|
| 用途 | 自宅の範囲・施設内の範囲への出入り検知（F4） |
| 使用ライブラリ | expo-location, expo-task-manager |
| 必要な権限 | 「常に許可」（バックグラウンドでの位置情報取得）。初回、自宅登録時にOSの許可ダイアログを表示する |
| 権限が得られない場合 | バックグラウンドでの自動判定ができない旨をアプリ内で案内し、アプリを開いたときだけ手動更新できるようにする（フォールバック） |
| 監視方式 | 自宅を中心とした同心円状の2つのジオフェンス（在宅判定用・施設内判定用）を同時に登録する。いずれかの境界をまたぐイベントが発生するたびに、その時点の現在地から改めて3段階のステータスを計算し直す |

## 4. Google Sheets API（簡易データベース）

| 項目 | 内容 |
|---|---|
| 用途 | Groups・Membersシートの読み書き |
| 認証方式 | サービスアカウント（JSON鍵）。鍵ファイルはAPIサーバー側の`.env`で管理し、Gitにはコミットしない |
| 保存場所の制約 | サービスアカウント自身はマイドライブを持たないため、対象スプレッドシートは共有ドライブ上に作成し、サービスアカウントを編集者として共有する |
| スコープ | `https://www.googleapis.com/auth/spreadsheets`（対象スプレッドシートのみ） |

## 5. ブラウザのService Worker / Push API（Web版）

| 項目 | 内容 |
|---|---|
| 用途 | F14・F15。Web版でのプッシュ通知の受信、通知タップ時のアプリ復帰、開いている画面への即時更新の合図送信 |
| 実体 | `server/public/sw.js`（オリジン直下に配置し、サイト全体のスコープを持たせる） |
| 主なイベント処理 | `push`：通知の表示＋開いている画面へ`postMessage`で更新の合図を送信。`notificationclick`：既存ウィンドウへのフォーカス、無ければ`clients.openWindow()`で新規に開く |
| 既知の制約 | iOSではアプリがバックグラウンドの間JSの実行が止まるため、`push`イベントの合図が画面に届かないことがある。この対策として、画面側は`visibilitychange`・`pageshow`イベントでも一覧を再取得する（Service Workerからの合図はベストエフォート、画面の可視化イベントを主な保険とする） |
