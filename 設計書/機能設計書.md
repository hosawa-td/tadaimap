# タダイマップ 機能設計書

各機能について、入力・出力・処理内容（業務ロジック）をまとめる。

## F1. 家族グループの作成

| 項目 | 内容 |
|---|---|
| 概要 | 新しい家族グループを作成し、招待コードを発行する |
| 入力 | 自分の名前（表示名） |
| 出力 | グループID、招待コード（6桁数字）、自分のメンバーID |
| 処理内容 | 1. 端末固有のデバイスIDを生成（初回起動時に端末内へ保存）。 2. グループIDを新規発行。 3. 招待コード（6桁の数字、重複しないもの）を発行し、**発行から7日間**を有効期限として記録する。 4. 入力された名前で、自分をこのグループの最初のメンバーとして登録する（名前表示設定は初期値ON）。 |

## F2. 招待コードでのグループ参加

| 項目 | 内容 |
|---|---|
| 概要 | 既存の家族グループに、招待コードを使って参加する |
| 入力 | 招待コード（6桁）、自分の名前（表示名） |
| 出力 | 参加したグループの情報、自分のメンバーID |
| 処理内容 | 1. 招待コードが存在し、有効期限内かを確認する。 2. 期限切れ、または存在しないコードの場合はエラーを返す（「コードが見つかりません」）。 3. 該当グループのメンバーとして、入力された名前で登録する（名前表示設定は初期値ON）。 4. **1台の端末は複数の家族グループに参加できる**（F18）。重複登録を防ぐため、同じグループへ同じ端末から重ねて参加しようとした場合のみエラーとする（別のグループへの参加は妨げない）。 |

## F3. 自宅位置・判定範囲の登録

| 項目 | 内容 |
|---|---|
| 概要 | 自宅の位置（緯度・経度）と、「在宅」「施設内」それぞれと判定する範囲（半径）を登録する |
| 入力 | 緯度、経度（現在地取得、または地図上での指定）、在宅判定の半径（50m〜300m、初期値100m）、施設内判定の半径（100m〜2000m、初期値300m、在宅判定の半径以上の値） |
| 出力 | 登録結果 |
| 処理内容 | 1. 端末の位置情報取得機能（OS機能）で緯度・経度を取得する。 2. 2つの半径とあわせて、自分のメンバー情報に保存する。施設内判定の半径は在宅判定の半径以上でなければならない（それより狭い値はエラー）。 3. 保存後、アプリ側でこの位置情報・2つの半径をもとに、OSへ2重のジオフェンス監視を登録する（F4）。 |

## F4. 在宅／施設内／外出の自動判定

| 項目 | 内容 |
|---|---|
| 概要 | 自宅の範囲・その一回り外側の範囲への出入りを検知し、「在宅」「施設内」「外出中」の3段階のステータスを自動更新する |
| 入力 | OSからのジオフェンス出入り通知（アプリ非起動時も含む） |
| 出力 | 更新後のステータス（home/nearby/away）、更新時刻 |
| 処理内容 | 1. F3で登録した位置・2つの半径をもとに、OSの位置情報機能へ2重のジオフェンス監視を登録する。 2. いずれかの境界をまたいだイベントが発生するたびに、その時点の現在地から自宅までの距離を計算し直し、在宅判定の半径以内なら「home」、それを超え施設内判定の半径以内なら「nearby」、それも超えていれば「away」と判定する（単一のイベントだけに頼らず、都度3段階を再計算する）。 3. 直前と判定結果が変わらない場合は、通信・通知を発生させない。 4. 変化した場合はサーバーへ状態とタイムスタンプを送信する。サーバーは受け取った内容でスプレッドシートのメンバー情報を更新し、在宅中の詳細な状態（F16）は自動的に空へ戻す。 5. 状態が変化した場合、同じグループの他メンバーへ通知要否を判定する（F9）。 |

## F5. ホーム画面（家族一覧）表示

| 項目 | 内容 |
|---|---|
| 概要 | 同じグループのメンバー全員の状態を一覧表示する |
| 入力 | グループID |
| 出力 | メンバーごとの「表示名（または匿名）」「ステータス（在宅／施設内＝呼び方／外出中）」「最終更新時刻」「在宅中のみ：詳細な状態」「管理者バッジ」、在宅人数 |
| 処理内容 | 1. サーバーへグループ内メンバーの最新状態を問い合わせる。 2. 各メンバーの「名前を家族に表示する」設定がOFFの場合は、名前を伏せて「メンバー」等の匿名表示にする（本人の行は常に本人の名前を表示）。 3. 在宅人数（在宅人数／総人数。「施設内」は在宅人数に含めない）を集計して表示する。 4. ステータスが「施設内」のメンバーは、固定文言ではなくグループ共通の「呼び方」（F13）を表示する。 5. ステータスが「在宅」かつ詳細な状態（F16）が設定されているメンバーは、それを小さく添えて表示する。 6. グループの管理者（F12）には管理者バッジを表示する。 7. 画面右上の「更新」ボタンで、いつでも手動で最新の状態を再取得できる。 |

## F6. 手動でのステータス切り替え

| 項目 | 内容 |
|---|---|
| 概要 | 自動判定を待たず、自分から「在宅」「施設内」「外出中」のいずれかへ切り替え、家族へ知らせる |
| 入力 | 3択の切替操作（ボタン押下） |
| 出力 | 切替結果、家族への通知（「施設内」への切替時を含む） |
| 処理内容 | 1. 自分のステータスを選択した値に更新する（F4の自動判定と同じ経路で更新）。 2. 同じグループの他メンバーへ、通知設定がONの端末に対してのみプッシュ通知を送信する（本文は「〜が帰宅しました」「〜が（呼び方）に移動しました」「〜が外出しました」）。 3. 切替に伴い、在宅中の詳細な状態（F16）は自動的に空へ戻る。 |

## F7. プロフィール・表示設定

| 項目 | 内容 |
|---|---|
| 概要 | 自分の名前の変更、および名前を家族に表示するかどうかの設定 |
| 入力 | 変更後の名前、名前表示設定（ON/OFF） |
| 出力 | 更新結果 |
| 処理内容 | 1. 入力内容でメンバー情報を更新する。 2. 表示設定は自分のみが変更でき、即座にホーム画面（F5）の表示へ反映される。 3. 「施設内」の呼び方は個人設定ではなくグループ共通の設定（F13）に分離されているため、本機能では扱わない。 |

## F8. 自宅設定の変更

| 項目 | 内容 |
|---|---|
| 概要 | 設定画面から、登録済みの自宅位置・判定範囲（在宅／施設内の両方）を変更する |
| 入力 | F3と同じ |
| 出力 | F3と同じ |
| 処理内容 | F3の登録内容を上書きする。変更後、ジオフェンス監視も新しい設定で登録し直す。 |

## F9. 通知設定

| 項目 | 内容 |
|---|---|
| 概要 | 家族の状態変化（在宅／施設内／外出）をプッシュ通知で知らせる機能のON/OFF |
| 入力 | 通知設定（ON/OFF） |
| 出力 | 更新結果 |
| 処理内容 | 1. 自動判定（F4）・手動切替（F6）のいずれについても、通知設定がOFFの端末へはプッシュ通知を送信しない。 2. 設定はメンバーごとに個別に保持する（自分が受け取るかどうかの設定であり、他人の通知有無には影響しない）。 3. 通知の送信経路は、ネイティブアプリを利用中の端末にはExpo Push、Web版（F14）を利用中の端末にはWeb Push（F15）を用いる。片方の送信に失敗しても、もう一方の送信や状態更新自体には影響しない。 |

## F10. 招待コードの確認・コピー

| 項目 | 内容 |
|---|---|
| 概要 | 設定画面で、自グループの招待コードを確認・コピーできる |
| 入力 | なし（表示のみ） |
| 出力 | 招待コード、有効期限 |
| 処理内容 | 招待コードが期限切れの場合は、その旨を表示し、再発行操作を提供する（再発行すると新しい7日間の有効期限のコードが発行され、古いコードは無効になる）。 |

## F11. グループからの退出

| 項目 | 内容 |
|---|---|
| 概要 | 参加している家族グループから抜ける |
| 入力 | 退出操作（確認ダイアログでの最終確認を含む） |
| 出力 | 退出結果、他に参加中のグループがあればその画面へ、無ければスタート画面への遷移 |
| 処理内容 | 1. 自分のメンバー情報をグループから削除する（他メンバーの一覧から見えなくなる）。 2. 端末内に保存していたそのグループの参加情報・自宅設定をクリアする。他に参加中のグループ（F18）が残っていればそちらへ切り替え、無ければスタート画面に戻す。 3. グループの最後の1人が退出した場合、グループ自体を削除する。 |

## F12. 管理者による代理でのステータス変更

| 項目 | 内容 |
|---|---|
| 概要 | グループの管理者が、他のメンバーのステータスを代わりに手動で変更できる |
| 権限 | グループを作成した人が自動的に管理者になる（1グループに1人。後から移譲する機能はない）。既存のグループ（管理者機能追加前に作成されたもの）では、作成日時が最も古いメンバーを暫定的に管理者とみなす |
| 入力 | 対象メンバーの選択（アプリ版：名前を長押し／Web版：名前をタップ）、変更後のステータス（3択） |
| 出力 | 変更結果、対象メンバー・家族への通知（F6と同じ） |
| 処理内容 | 1. 操作者が対象メンバーと同じグループの管理者であることをサーバー側で確認する（管理者以外や本人以外からの操作は拒否）。 2. 確認後はF6と同じ経路でステータスを更新する。 |
| 画面 | 対象メンバーをタップ（長押し）すると、状態変更の3択に加えて「このメンバーを削除する」（F19）を含むダイアログ（ボトムシート）が開く。アプリ版・Web版とも、ダイアログの外側（背景の暗い部分）をタップすると、何も変更せずに閉じられる |

## F13. 呼び方（「施設内」ステータスの表示名）の設定

| 項目 | 内容 |
|---|---|
| 概要 | 「施設内」ステータスの表示名（初期値「施設内」、例：「ロビー」）を、グループ共通の1つの値として設定する |
| 権限 | 管理者のみ変更できる。管理者以外の設定画面には、現在の値が読み取り専用で表示される |
| 入力 | 呼び方の文字列（1〜12文字） |
| 出力 | 更新結果。以後、グループ全員のホーム画面・通知文言に反映される |
| 処理内容 | 1. グループ情報（呼び方）を更新する。 2. 更新後は、全メンバーの一覧表示・手動切替ボタンのラベル・通知文言のすべてに同じ値が使われる。 |

## F14. Web版（ブラウザ簡易画面）

| 項目 | 内容 |
|---|---|
| 概要 | ネイティブアプリを入れられない端末（主にiPhone）向けに、招待コード参加・一覧表示・手動でのステータス切替・各種設定をブラウザだけで行える簡易画面を提供する |
| 対応機能 | グループ参加（F2）、複数グループの参加・切替（F18）、一覧表示（F5）、手動でのステータス切替（F6、3択）、管理者による代理変更（F12）、管理者によるメンバー削除（F19）、管理者によるグループ削除（F20）、呼び方の設定（F13）、名前・表示設定（F7）、在宅中の詳細な状態（F16）、通知設定（F9、Web Push）、招待コードでの参加のみ（グループ作成はネイティブアプリのみ）、グループからの退出（F11）、自宅登録・画面を開いた瞬間だけの簡易自動判定（F22） |
| 制約 | バックグラウンドでの位置情報監視ができないため、アプリ版のような継続的な自動判定（F4）は行わない。自宅を登録した場合のみ、ページを開いた瞬間の1回に限り簡易的な自動判定（F22）を行う。画面を開いたまま自動更新されるのは、通知を受信した瞬間（Service Workerからの合図）と、画面が再び表示状態になった瞬間（アプリ切替・ホーム画面からの再起動時）のみで、それ以外は「更新」ボタンでの手動更新、またはページの再読み込みが必要 |
| 処理内容 | ネイティブアプリと同じAPIサーバーのエンドポイントを、端末ごとに発行した`device_id`（ブラウザのlocalStorageに保存）を使って呼び出す。ログイン機能は持たない点もネイティブアプリと同様 |
| 保存の耐障害性 | iPhoneのSafariでは、端末や設定によりlocalStorageの内容が失われ、招待コード入力画面に戻ってしまうことがある（原因を完全には制御できないiOS側の挙動）。これを緩和するため、参加情報（端末ID・参加中グループ一覧）はlocalStorageに加えてcookie（有効期限1年）にも複製しておき、起動時にlocalStorageが空の場合はcookieから復元する |

## F15. Web版のプッシュ通知（Web Push）

| 項目 | 内容 |
|---|---|
| 概要 | Web版でも、家族の状態変化をプッシュ通知で受け取れるようにする |
| 入力 | 通知の許可操作（ブラウザの許可ダイアログ） |
| 出力 | 購読情報の登録、以後の通知受信 |
| 処理内容 | 1. Service Worker（`sw.js`）を登録し、ブラウザ標準のPush APIで購読情報（endpoint・鍵）を作成する。 2. 購読情報をサーバーに登録する。 3. 状態変化時、サーバーはこの購読情報宛にWeb Push（VAPID）で通知を送る。 4. 通知受信時、Service Workerは通知の表示と同時に、開いている画面へ「一覧を更新して」という合図を送る（F5の即時更新）。 |
| 重要な制約 | **iPhoneのSafariでは、ページを普通のタブで開いているだけでは通知を受信できない**。一度「ホーム画面に追加」し、そのアイコンから開いた場合のみ有効になる（iOS 16.4以降が必要）。この条件を満たさない場合は、その旨を画面に案内する。 |

## F16. 在宅中の詳細な状態

| 項目 | 内容 |
|---|---|
| 概要 | ステータスが「在宅」の間、「トイレ中」「入浴中」など任意の一言メモを添えられる |
| 権限 | 本人のみ設定できる（管理者による代理設定は不可） |
| 入力 | 自由入力の文字列（0〜12文字、空文字は未設定に戻すことを意味する） |
| 出力 | 更新結果。ホーム画面の一覧に、対象メンバーの行へ小さく表示される |
| 処理内容 | 1. 入力欄からの離脱・キーボードの確定操作・「更新」ボタン・「×」ボタン（即クリア）のいずれかで保存する。 2. ステータスが「在宅」以外に変わったとき（F4・F6・F12のいずれの経路でも）、この値は自動的に空へ戻す（次に在宅になったときに前回の内容が残らないようにするため）。 3. 在宅人数のカウント（F5）には影響しない。 |

## F17. 一覧の手動更新

| 項目 | 内容 |
|---|---|
| 概要 | ホーム画面の右上（Web版も同様）にある「更新」ボタンで、家族全員の最新の状態をいつでも手動で取得し直せる |
| 入力 | 更新操作（ボタン押下） |
| 出力 | 最新化された一覧 |
| 処理内容 | サーバーへメンバー一覧を再取得し、画面を再描画する（アプリ版は既存の定期更新・pull-to-refreshに加えたショートカット、Web版は自動更新が限定的なための主な更新手段）。 |

## F18. 複数の家族グループへの参加・切替

| 項目 | 内容 |
|---|---|
| 概要 | 1台の端末（1人）が、複数の家族グループ（例：自分の実家・配偶者の実家）に参加し、設定画面から表示するグループを切り替えられる |
| 入力 | 切替先グループの選択、「別の招待コードで参加する」操作（F2を再利用） |
| 出力 | 切替後のホーム画面（メンバー一覧・自分の状態など、すべて切替先グループのものに入れ替わる） |
| 処理内容 | 1. 参加中のグループ一覧（グループID・メンバーID・そのグループでの自分の名前・招待コード）を端末内に保持する。 2. 設定画面に、2件以上参加している場合のみ一覧を表示し、いま表示中のグループが分かるようにする。一覧の各行には、見分けやすいよう招待コードもあわせて表示する。 3. 切替操作を行うと、該当グループのメンバーIDに切り替えてホーム画面を再取得する。 4. 「別の招待コードで参加する」は、既存の参加をそのまま保持したままF2の参加処理を行い、参加後は新しいグループへ自動的に切り替える。 |
| DBとの同期 | 端末内の保存内容は「キャッシュ」であり、正しさの根拠(source of truth)は常にDB側とする。アプリ起動時・設定画面を開いたとき（Web版は画面を開いたとき・更新のたび）に、この端末のdevice_idが実際にDB上でどのグループに参加しているかを問い合わせ（`GET /memberships`）、端末内の一覧をその結果で置き換える。これにより、端末の保存領域が失われた場合（再インストール等）や、他の端末での退出・削除によって内容がずれた場合でも、参加中のグループへ正しく復元・同期できる |
| 制約 | 自宅位置・判定範囲（F3）にもとづく自動判定（F4）は、実際に位置情報を監視できるのが1件のみのため、直近にF3/F8を行ったグループ（＝物理的に同じ自宅）に対してのみ働く。他のグループでは手動切替（F6）のみで状態を伝える運用になる |

## F19. 管理者によるメンバーの削除

| 項目 | 内容 |
|---|---|
| 概要 | グループの管理者が、自分以外のメンバーをグループから削除する |
| 権限 | 管理者のみ（F12と同じ判定）。自分自身の削除はこの機能では行わず、グループからの退出（F11）を使う |
| 入力 | 対象メンバーの選択（F12のダイアログ内「このメンバーを削除する」）、確認ダイアログでの最終確認 |
| 出力 | 削除結果。削除されたメンバーの端末は、そのグループの一覧が見られなくなる（再度参加するには招待コードが必要） |
| 処理内容 | 1. 操作者が対象メンバーと同じグループの管理者であることをサーバー側で確認する。 2. 確認後、対象メンバーの情報をグループから削除する（F11の退出処理と同じ削除経路を、本人以外からの操作として実行する）。 |

## F20. 管理者によるグループの削除

| 項目 | 内容 |
|---|---|
| 概要 | グループの管理者が、グループそのものを削除する（参加している全員がまとめて削除される） |
| 権限 | 管理者のみ |
| 入力 | 削除操作、確認ダイアログでの最終確認（取り消せない旨を明示） |
| 出力 | 削除結果。参加していた全員の端末で、このグループの一覧が見られなくなる |
| 処理内容 | 1. 操作者がこのグループの管理者であることをサーバー側で確認する。 2. 確認後、このグループに属する全メンバーの情報と、グループ自体の情報を削除する。 3. 削除操作をした本人の端末は、他に参加中のグループがあればそちらへ切り替え、無ければスタート画面に戻す（F11と同じ後処理）。他のメンバーの端末は、次にそのグループを開こうとした時点で「グループが見つかりません」となる。 |

## F21. ホーム画面の家族一覧の並び替え（アプリ版）

| 項目 | 内容 |
|---|---|
| 概要 | ホーム画面の家族一覧を、ドラッグ＆ドロップで自由に並び替えられる |
| 範囲 | この端末だけの表示順であり、他のメンバーの画面や、サーバー・DBには一切影響しない（見た目だけのローカル設定） |
| 入力 | 各行左端のハンドルアイコンを押したままドラッグして並び替える |
| 出力 | 並び替え後の一覧表示 |
| 処理内容 | 1. 並び順（メンバーIDの並び）を、グループごとに端末内へ保存する。 2. まだ並び替えを行っていない場合の既定の並びは、自分を先頭、それ以外はサーバーから取得した順とする。 3. 一覧を再取得するたびに、保存済みの並び順を適用する。並び順に記録の無い新しいメンバー（新規参加者）は末尾に追加する。 4. 実装は`react-native-draggable-flatlist`（`react-native-gesture-handler`・`react-native-reanimated`に依存）を使用する。 |
| 備考 | Web版には対応しない（対象読者・操作性の観点から、当面はアプリ版のみ） |

## F22. Web版の自宅登録・画面を開いた瞬間だけの簡易自動判定

| 項目 | 内容 |
|---|---|
| 概要 | Web版でも、設定画面から「現在地を自宅として登録する」ことができ、登録済みの場合はホーム画面を開いた瞬間（ページの読み込み・再読み込み）に一度だけ現在地を取得し、在宅／施設内／外出中を自動判定して必要なら状態を更新する |
| 入力 | 「現在地を自宅として登録する」操作（ブラウザの位置情報許可ダイアログを含む） |
| 出力 | 自宅位置の登録結果。判定が変化した場合はステータス更新・家族への通知（F6と同じ経路） |
| 処理内容 | 1. 「現在地を自宅として登録する」ボタンで、ブラウザの位置情報から緯度・経度を取得し、判定範囲は初期値（在宅100m・施設内300m、F3と同じ初期値）で登録する（`PATCH /members/:memberId/home`を利用、地図やスライダーは提供しない簡易版）。 2. メンバー一覧取得（F5）のレスポンスに、本人の行にのみ自宅位置・判定範囲を含める（他メンバーの位置情報を見せないため、他人の行では常にnull）。 3. ホーム画面を開いた瞬間（ページ読み込み時）に、自宅が登録済みであれば一度だけ現在地を取得し、F4と同じ計算式で在宅／施設内／外出中を判定する。判定結果が現在のステータスと異なる場合のみ、自動で状態を更新する（source="auto"）。 4. 位置情報が取得できない・許可されなかった場合は、エラー表示をせず静かに手動切替へフォールバックする。 5. この自動判定は「ページを開いた瞬間の1回」に限られ、アプリ版のようなバックグラウンドでの継続監視は行わない（開いている間の継続監視・タブがバックグラウンドの間の監視は行わない）。 |
