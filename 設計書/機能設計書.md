# タダイマップ 機能設計書

各機能について、入力・出力・処理内容（業務ロジック）をまとめる。

## F1. 家族グループの作成

| 項目 | 内容 |
|---|---|
| 概要 | 新しい家族グループを作成し、招待コードを発行する |
| 入力 | 自分の名前（表示名） |
| 出力 | グループID、招待コード（6桁数字）、自分のメンバーID |
| 処理内容 | 1. 端末固有のデバイスIDを生成（初回起動時に端末内へ保存）。 2. グループIDを新規発行。 3. 招待コード（6桁の数字、重複しないもの）を発行し、**発行から7日間**を有効期限として記録する。 4. 入力された名前で、自分をこのグループの最初のメンバーとして登録する（名前表示設定は初期値ON）。 |

## F2. 招待コードでのグループ参加

| 項目 | 内容 |
|---|---|
| 概要 | 既存の家族グループに、招待コードを使って参加する |
| 入力 | 招待コード（6桁）、自分の名前（表示名） |
| 出力 | 参加したグループの情報、自分のメンバーID |
| 処理内容 | 1. 招待コードが存在し、有効期限内かを確認する。 2. 期限切れ、または存在しないコードの場合はエラーを返す（「コードが見つかりません」）。 3. 同じグループ内に、入力された名前と完全に一致する既存メンバーがいる場合は、新規登録ではなく**そのメンバーとして復帰させる**（`device_id`をこの端末のものへ置き換える。ステータス・管理者権限・自宅設定などはそのまま引き継がれる）。端末の機種変更・アプリの再インストール等で端末側の識別情報が失われた場合に、同じ名前で入力し直すだけで元の状態へ戻れるようにするための仕様。 4. 一致する名前が無い場合は、入力された名前で新規メンバーとして登録する（名前表示設定は初期値ON）。 5. **1台の端末は複数の家族グループに参加できる**（F18）。重複登録を防ぐため、同じグループへ同じ端末から重ねて参加しようとした場合のみエラーとする（別のグループへの参加は妨げない）。 6. （アプリ版のみ）復帰の場合で、かつ既に自宅位置・判定範囲が登録済みの場合は、その内容をレスポンスに含めて返す。アプリ側はこれを使ってこの端末でもジオフェンス監視を再登録し、「自宅の登録画面」（F3）を省略してホーム画面（F5）へ直接進む（新規登録の場合や、まだ自宅未登録の復帰の場合は、これまで通り自宅の登録画面に進む）。 |
| 注意点 | 同じグループ内で名前が完全一致した場合は自動的に復帰扱いになるため、複数人が同じ表示名（例：全員「お母さん」）を使っている場合、後から参加した人が先の人のメンバーを意図せず乗っ取ってしまう可能性がある。この仕組みは、招待コードさえ知っていれば誰の名前でも参加できるという本アプリの元々の信頼モデル（パスワード等の認証を持たない家族内利用が前提）を踏まえた設計であり、同じ表示名を複数人が使うことは避けるよう案内する。 |

## F3. 自宅位置・判定範囲の登録

| 項目 | 内容 |
|---|---|
| 概要 | 自宅の位置（緯度・経度）と、「在宅」「施設内」それぞれと判定する範囲（半径）を登録する |
| 入力 | 緯度、経度（現在地取得、または地図上での指定）、在宅判定の半径（50m〜300m、初期値100m）、施設内判定の半径（100m〜2000m、初期値300m、在宅判定の半径以上の値） |
| 出力 | 登録結果 |
| 処理内容 | 1. 端末の位置情報取得機能（OS機能）で緯度・経度を取得する。地図の操作（「設定位置」「現在地」ボタン、「近くにいる」GPS判定のオン／オフ）はF29を参照。 2. 2つの半径とあわせて、自分のメンバー情報に保存する。施設内判定の半径は在宅判定の半径以上でなければならない（それより狭い値はエラー）。 3. 保存後、アプリ側でこの位置情報・2つの半径をもとに、OSへ2重のジオフェンス監視を登録する（F4）。 |

## F4. 在宅／施設内／外出の自動判定

| 項目 | 内容 |
|---|---|
| 概要 | 自宅の範囲・その一回り外側の範囲への出入りを検知し、「在宅」「施設内」「外出中」の3段階のステータスを自動更新する |
| 入力 | OSからのジオフェンス出入り通知（アプリ非起動時も含む）。自宅Wi-Fi（F24）を登録している場合は、Wi-Fiへの接続通知・定期確認も加わる |
| 出力 | 更新後のステータス（home/nearby/away）、更新時刻 |
| 処理内容 | 1. F3で登録した位置・2つの半径をもとに、OSの位置情報機能へ2重のジオフェンス監視を登録する。 2. いずれかの境界をまたいだイベントが発生するたびに、その時点の現在地から自宅までの距離を計算し直し、在宅判定の半径以内なら「home」、それを超え施設内判定の半径以内なら「nearby」、それも超えていれば「away」と判定する（単一のイベントだけに頼らず、都度3段階を再計算する）。自宅Wi-Fi（F24）を登録している場合は、F24の判定ルールを優先する。 3. 直前と判定結果が変わらない場合は、通信・通知を発生させない。 4. 変化した場合はサーバーへ状態とタイムスタンプを送信する。サーバーは受け取った内容でスプレッドシートのメンバー情報を更新し、在宅中の詳細な状態（F16）は自動的に空へ戻す。 5. 状態が変化した場合、同じグループの他メンバーへ通知要否を判定する（F9）。 |

## F5. ホーム画面（家族一覧）表示

| 項目 | 内容 |
|---|---|
| 概要 | 同じグループのメンバー全員の状態を一覧表示する |
| 入力 | グループID |
| 出力 | メンバーごとの「表示名（または匿名）」「ステータス（在宅／施設内＝呼び方／外出中）」「最終更新時刻（管理者による代理変更の直後を除く）」「在宅中のみ：詳細な状態」「管理者バッジ」、在宅人数 |
| 処理内容 | 1. サーバーへグループ内メンバーの最新状態を問い合わせる。 2. 各メンバーの「名前を家族に表示する」設定がOFFの場合は、名前を伏せて「メンバー」等の匿名表示にする（本人の行は常に本人の名前を表示）。 3. 在宅人数（在宅人数／総人数。「施設内」は在宅人数に含めない）を集計して表示する。 4. ステータスが「施設内」のメンバーは、固定文言ではなくグループ共通の「呼び方」（F13）を表示する。 5. ステータスが「在宅」かつ詳細な状態（F16）が設定されているメンバーは、それを小さく添えて表示する。 6. グループの管理者（F12）には管理者バッジを表示する。 7. 画面右上の「更新」ボタンで、いつでも手動で最新の状態を再取得できる。 8. 直近の変更が管理者による代理変更（F12）である間は、時刻を表示せずステータスのラベルのみを表示する。 |

## F6. 手動でのステータス切り替え

| 項目 | 内容 |
|---|---|
| 概要 | 自動判定を待たず、自分から「在宅」「施設内」「外出中」のいずれかへ切り替え、家族へ知らせる |
| 入力 | 3択の切替操作（ボタン押下） |
| 出力 | 切替結果、家族への通知（「施設内」への切替時を含む） |
| 処理内容 | 1. 自分のステータスを選択した値に更新する（F4の自動判定と同じ経路で更新）。 2. 同じグループの他メンバーへ、通知設定がONの端末に対してのみプッシュ通知を送信する（本文は「〜が帰宅しました」「〜が（呼び方）に移動しました」「〜が外出しました」）。 3. 切替に伴い、在宅中の詳細な状態（F16）は自動的に空へ戻る。 |

## F7. プロフィール・表示設定

| 項目 | 内容 |
|---|---|
| 概要 | 自分の名前の変更、および名前を家族に表示するかどうかの設定 |
| 入力 | 変更後の名前、名前表示設定（ON/OFF） |
| 出力 | 更新結果 |
| 処理内容 | 1. 入力内容でメンバー情報を更新する。 2. 表示設定は自分のみが変更でき、即座にホーム画面（F5）の表示へ反映される。 3. 「施設内」の呼び方は個人設定ではなくグループ共通の設定（F13）に分離されているため、本機能では扱わない。 |

## F8. 自宅設定の変更

| 項目 | 内容 |
|---|---|
| 概要 | 設定画面から、登録済みの自宅位置・判定範囲（在宅／施設内の両方）を変更する |
| 入力 | F3と同じ |
| 出力 | F3と同じ |
| 処理内容 | F3の登録内容を上書きする。変更後、ジオフェンス監視も新しい設定で登録し直す。 |

## F9. 通知設定

| 項目 | 内容 |
|---|---|
| 概要 | 家族の状態変化（在宅／施設内／外出）をプッシュ通知で知らせる機能のON/OFF |
| 入力 | 通知設定（ON/OFF） |
| 出力 | 更新結果 |
| 処理内容 | 1. 自動判定（F4）・手動切替（F6）のいずれについても、通知設定がOFFの端末へはプッシュ通知を送信しない。 2. 設定はメンバーごとに個別に保持する（自分が受け取るかどうかの設定であり、他人の通知有無には影響しない）。 3. 通知の送信経路は、ネイティブアプリを利用中の端末にはExpo Push、Web版（F14）を利用中の端末にはWeb Push（F15）を用いる。片方の送信に失敗しても、もう一方の送信や状態更新自体には影響しない。 |

## F10. 招待コードの確認・コピー

| 項目 | 内容 |
|---|---|
| 概要 | 設定画面で、自グループの招待コードを確認・コピーできる |
| 入力 | なし（表示のみ） |
| 出力 | 招待コード、有効期限 |
| 処理内容 | 招待コードが期限切れの場合は、その旨を表示し、再発行操作を提供する（再発行すると新しい7日間の有効期限のコードが発行され、古いコードは無効になる）。 |

## F11. グループからの退出

| 項目 | 内容 |
|---|---|
| 概要 | 参加している家族グループから抜ける |
| 入力 | 退出操作（確認ダイアログでの最終確認を含む） |
| 出力 | 退出結果、他に参加中のグループがあればその画面へ、無ければスタート画面への遷移 |
| 処理内容 | 1. 自分のメンバー情報をグループから削除する（他メンバーの一覧から見えなくなる）。 2. 端末内に保存していたそのグループの参加情報・自宅設定をクリアする。他に参加中のグループ（F18）が残っていればそちらへ切り替え、無ければスタート画面に戻す。 3. グループの最後の1人が退出した場合、グループ自体を削除する。 |

## F12. 管理者による代理でのステータス変更

| 項目 | 内容 |
|---|---|
| 概要 | グループの管理者が、他のメンバーのステータスを代わりに手動で変更できる |
| 権限 | グループを作成した人が自動的に管理者になる（1グループに1人。後から移譲する機能はない）。既存のグループ（管理者機能追加前に作成されたもの）では、作成日時が最も古いメンバーを暫定的に管理者とみなす |
| 入力 | 対象メンバーの選択（アプリ版：名前を長押し／Web版：名前をタップ）、変更後のステータス（3択） |
| 出力 | 変更結果。F6と異なり、家族への通知は送らない |
| 処理内容 | 1. 操作者が対象メンバーと同じグループの管理者であることをサーバー側で確認する（管理者以外や本人以外からの操作は拒否）。 2. ステータスを更新する（在宅中の詳細な状態(F16)は自動的に空へ戻る点はF6と同じ）。ただしF6と異なり、(a)家族へのプッシュ通知は送らない、(b)帰宅・外出の時刻（`status_updated_at`）は更新しない。管理者が代わりに押しただけで、本人が実際にそのタイミングで帰宅・外出したわけではないため。 3. 一覧表示（F5）では、直近の変更が管理者による代理変更である間（`statusSetByAdmin`）は、ステータスのラベル（「在宅」等）のみを表示し、時刻（「11/18(水) 18:32に帰宅」等）は表示しない。本人が改めて自分で切り替える（F6）と、通常どおり通知・時刻表示が有効な状態に戻る。 |
| 画面 | 対象メンバーをタップ（長押し）すると、状態変更の3択に加えて「このメンバーを削除する」（F19）を含むダイアログ（ボトムシート）が開く。アプリ版・Web版とも、ダイアログの外側（背景の暗い部分）をタップすると、何も変更せずに閉じられる |

## F13. 呼び方（「施設内」ステータスの表示名）の設定

| 項目 | 内容 |
|---|---|
| 概要 | 「施設内」ステータスの表示名（初期値「施設内」、例：「ロビー」）を、グループ共通の1つの値として設定する |
| 権限 | 管理者のみ変更できる。管理者以外の設定画面には、現在の値が読み取り専用で表示される |
| 入力 | 呼び方の文字列（1〜12文字） |
| 出力 | 更新結果。以後、グループ全員のホーム画面・通知文言に反映される |
| 処理内容 | 1. グループ情報（呼び方）を更新する。 2. 更新後は、全メンバーの一覧表示・手動切替ボタンのラベル・通知文言のすべてに同じ値が使われる。 |

## F14. Web版（ブラウザ簡易画面）

| 項目 | 内容 |
|---|---|
| 概要 | ネイティブアプリを入れられない端末（主にiPhone）向けに、招待コード参加・一覧表示・手動でのステータス切替・各種設定をブラウザだけで行える簡易画面を提供する |
| 対応機能 | グループ参加（F2）、複数グループの参加・切替（F18）、一覧表示（F5）、一覧の並び替え（F21）、手動でのステータス切替（F6、3択）、管理者による代理変更（F12）、管理者によるメンバー削除（F19）、管理者によるグループ削除（F20）、呼び方の設定（F13）、名前・表示設定（F7）、在宅中の詳細な状態（F16）、通知設定（F9、Web Push）、招待コードでの参加のみ（グループ作成はネイティブアプリのみ）、グループからの退出（F11）、自宅登録・画面を開いた瞬間だけの簡易自動判定（F22） |
| 制約 | バックグラウンドでの位置情報監視ができないため、アプリ版のような継続的な自動判定（F4）は行わない。自宅を登録した場合のみ、ページを開いた瞬間の1回に限り簡易的な自動判定（F22）を行う。画面を開いたまま自動更新されるのは、通知を受信した瞬間（Service Workerからの合図）と、画面が再び表示状態になった瞬間（アプリ切替・ホーム画面からの再起動時）のみで、それ以外は「更新」ボタンでの手動更新、またはページの再読み込みが必要 |
| 処理内容 | ネイティブアプリと同じAPIサーバーのエンドポイントを、端末ごとに発行した`device_id`（ブラウザのlocalStorageに保存）を使って呼び出す。ログイン機能は持たない点もネイティブアプリと同様 |
| 保存の耐障害性 | iPhoneのSafariでは、端末や設定によりlocalStorageの内容が失われ、招待コード入力画面に戻ってしまうことがある（原因を完全には制御できないiOS側の挙動）。これを緩和するため、参加情報（端末ID・参加中グループ一覧）はlocalStorageに加えてcookie（有効期限1年）にも複製しておき、起動時にlocalStorageが空の場合はcookieから復元する |

## F15. Web版のプッシュ通知（Web Push）

| 項目 | 内容 |
|---|---|
| 概要 | Web版でも、家族の状態変化をプッシュ通知で受け取れるようにする |
| 入力 | 通知の許可操作（ブラウザの許可ダイアログ） |
| 出力 | 購読情報の登録、以後の通知受信 |
| 処理内容 | 1. Service Worker（`sw.js`）を登録し、ブラウザ標準のPush APIで購読情報（endpoint・鍵）を作成する。 2. 購読情報をサーバーに登録する。 3. 状態変化時、サーバーはこの購読情報宛にWeb Push（VAPID）で通知を送る。 4. 通知受信時、Service Workerは通知の表示と同時に、開いている画面へ「一覧を更新して」という合図を送る（F5の即時更新）。 |
| 重要な制約 | **iPhoneのSafariでは、ページを普通のタブで開いているだけでは通知を受信できない**。一度「ホーム画面に追加」し、そのアイコンから開いた場合のみ有効になる（iOS 16.4以降が必要）。この条件を満たさない場合は、その旨を画面に案内する。 |

## F16. 在宅中の詳細な状態

| 項目 | 内容 |
|---|---|
| 概要 | ステータスが「在宅」の間、「トイレ中」「入浴中」など任意の一言メモを添えられる |
| 権限 | 本人のみ設定できる（管理者による代理設定は不可） |
| 入力 | 自由入力の文字列（0〜12文字、空文字は未設定に戻すことを意味する） |
| 出力 | 更新結果。ホーム画面の一覧に、対象メンバーの行へ小さく表示される |
| 処理内容 | 1. 入力欄からの離脱・キーボードの確定操作・「更新」ボタン・「×」ボタン（即クリア）のいずれかで保存する。 2. ステータスが「在宅」以外に変わったとき（F4・F6・F12のいずれの経路でも）、この値は自動的に空へ戻す（次に在宅になったときに前回の内容が残らないようにするため）。 3. 在宅人数のカウント（F5）には影響しない。 |

## F17. 一覧の手動更新

| 項目 | 内容 |
|---|---|
| 概要 | ホーム画面の右上（Web版も同様）にある「更新」ボタンで、家族全員の最新の状態をいつでも手動で取得し直せる |
| 入力 | 更新操作（ボタン押下） |
| 出力 | 最新化された一覧 |
| 処理内容 | サーバーへメンバー一覧を再取得し、画面を再描画する（アプリ版は既存の定期更新・pull-to-refreshに加えたショートカット、Web版は自動更新が限定的なための主な更新手段）。 |

## F18. 複数の家族グループへの参加・切替

| 項目 | 内容 |
|---|---|
| 概要 | 1台の端末（1人）が、複数の家族グループ（例：自分の実家・配偶者の実家）に参加し、設定画面から表示するグループを切り替えられる |
| 入力 | 切替先グループの選択、「別の招待コードで参加する」操作（F2を再利用） |
| 出力 | 切替後のホーム画面（メンバー一覧・自分の状態など、すべて切替先グループのものに入れ替わる） |

## F24. 自宅Wi-Fiによる在宅判定（アプリ版・Android）

| 項目 | 内容 |
|---|---|
| 概要 | 自宅のWi-Fiにつながっているかどうかで、マンションの自分の部屋（例：9F）にいるのか、同じ建物内の別の場所（1Fロビー・ごみ置き場・駐車場等）にいるのかを見分ける。GPSでは建物内の高さ（階）や数十m以内の位置を見分けられないため、部屋の中でしか届かない自宅Wi-Fiを手がかりにする |
| 入力 | 設定画面の「自宅のWi-Fi」欄の「登録」操作（その時点で接続中のWi-Fi名を登録する）、「登録を解除する」操作。登録後は、OSからのWi-Fi接続通知・定期確認（アプリ非起動時も含む） |
| 出力 | 更新後のステータス（F4と同じ経路でサーバーへ送信） |
| 処理内容 | 1. 登録操作で、いま接続中のWi-Fi名（SSID）を読み取り、**端末内にのみ**保存する（家族に見せる必要の無い情報のため、サーバーには送らない）。Wi-Fiがオフ・未接続・Wi-Fi名が読めない（位置情報の権限不足）場合は、理由を示して登録しない。 2. 登録後、次の3つのきっかけで、F4と同じく3段階のステータスを計算し直す。(a) ジオフェンスの出入り（F4）、(b) いずれかのWi-Fiへの接続（OSのネットワーク監視。アプリが閉じられていてもOSが起こす）、(c) 約15分ごとの定期確認（OSの都合でWi-Fiが**切れた瞬間**は通知されないため。v1.4.1以降は、自宅が登録されていれば自宅Wi-Fiの登録有無にかかわらず毎回判定し直し、ジオフェンスの取りこぼしも拾う）、(d) アプリを開いたとき（起動時・裏から戻ったとき）。判定結果は、サーバー上の自分の現在のステータスと比べて、異なる場合だけ送信する（通信できないときは端末に覚えた前回値と比べる）。現在地が取れなかった場合は、ジオフェンスの出入りイベントの内容（どの範囲に入った・出た）から判定する。 3. 登録できるWi-Fiは「自宅のWi-Fi」と「別の部屋のWi-Fi」の2種類で、それぞれ複数登録できる（v1.4.3以降。端末の保存済みWi-Fi一覧はAndroidの制限で読めないため、登録はその時点で接続中のWi-Fiからのみ。同じWi-Fiを別の種類で登録し直すと種類が入れ替わる）。判定ルール：(0) 別の部屋のWi-Fiに接続中なら、現在地に関係なく「nearby」（グループ共通の呼び方（F13）は変更しない。このときも現在地は取得しない）。(i) 自宅Wi-Fiに接続中なら、距離に関係なく「home」（屋内でGPSがずれても在宅と判定するため。このときは電池節約のため現在地を取得しない）。(ii) 自宅Wi-Fiに接続していない場合、施設内判定の半径を超えていれば「away」、半径以内なら在宅判定の半径以内であっても「nearby」（グループ共通の呼び方（F13）で表示）。(iii) 端末のWi-Fiがオフ、またはWi-Fi名が読めない場合は判断材料にならないため、従来の距離だけの判定（F4）に戻す。ただし設定画面の「別の階・別の部屋を区別する」（厳密モード、v1.4.2以降・初期値オフ・端末内にのみ保存）がオンの場合は、自宅Wi-Fiにつながっていない扱いとし、施設内判定の半径以内なら「nearby」にする（別の階の部屋でWi-Fiをオフにしていても在宅にしないため。半径を超えていれば「away」）。ジオフェンスの出入りからの判定（現在地が取れない場合）にも同じ扱いを適用する。(iv) Wi-Fiにつながっておらず現在地も取れない場合は、ステータスを変更しない。 4. 登録した直後にも一度判定を行い、その時点の状態を反映する。 5. 「登録を解除する」で、Wi-Fi名の保存と見張りをやめ、F4の距離だけの判定に戻す。グループからの退出（F11）で参加中のグループが無くなった場合も、Wi-Fi名を消去する。 6. 見張り（ジオフェンス・Wi-Fi接続）は、端末の再起動後もアプリを開かずに再開される（再起動通知の権限で、OSに登録し直す）。 |
| 制約 | Android版のみ（iOS・Web版では設定欄自体を表示しない）。Wi-Fiが切れたことの反映は定期確認に頼るため、最大で15分程度（端末の省電力状態によってはそれ以上）遅れる。ごみ出しなどの短い外出は反映されないことがある。メッシュWi-Fi等で同じ名前のWi-Fiが1Fまで届く建物では、1Fにいても「在宅」と判定される |

## F25. iPhoneのショートカットによる自動切替（Web版の補助）

| 項目 | 内容 |
|---|---|
| 概要 | Web版（主にiPhone）は画面を閉じている間に動けず、Wi-Fi名も読めないため、iPhone標準の「ショートカット」アプリのオートメーション（自宅Wi-Fiへの接続・切断をきっかけに実行）から、ステータス更新APIを直接呼び出して自動で状態を切り替えられるようにする。Web版の設定画面には、その設定に必要な情報と作り方を表示する |
| 入力 | Web版の設定画面の「設定用の情報を表示する」操作。設定後は、iPhoneのオートメーション（自宅Wi-Fiへの接続／接続解除） |
| 出力 | 設定画面：送信先URL・端末IDとそれぞれの「コピー」ボタン、ショートカットの作り方（帰宅用・外出用）。オートメーション実行時：ステータスの更新（F6と同じ`PATCH /members/:memberId/status`、通知もF6と同じ） |

## F26. 接続状況ログの取得・アップロード（Web版・Android版、解析用）

| 項目 | 内容 |
|---|---|
| 概要 | iPhoneのWeb版で、夜間にWi-Fiが切れて「外出中」のままになる現象が、一瞬の切断なのか継続的な切断なのかを後から解析できるよう、接続状況のログを取得してサーバーに保存する（v1.4.5）。v1.4.7でAndroid版にも、自動判定の動作ログの取得を追加した（下の「Android版の追加」） |
| 入力 | Web版の画面の表示/非表示・オンライン/オフライン・通信失敗などの出来事。iPhoneのショートカットや画面操作によるステータス変更要求 |
| 出力 | `Logs`シートへの追記。閲覧は`GET /diag/logs`（環境変数`DIAG_TOKEN`が必要） |
| 処理内容 | 1. 端末側：`boot`・`visible`・`hidden`・`online`・`offline`・`pageshow`・`pagehide`・`freeze`・`resume`・`fetch_error`（通信失敗）・`gap`（前回の動作から2分以上空いた＝画面が止まっていた）を、接続状態（オンライン可否・接続種別）とともに端末内（localStorage、最大300件）に貯める。画面が見える状態になったとき・オンラインに戻ったとき・画面を閉じるとき・起動時に`POST /members/:memberId/logs`でまとめて送り、送信できたものは端末から消す（通信できない間は貯めたままにする）。 2. サーバー側：`PATCH /members/:memberId/status`を受けるたびに、変更前後の状態・送信元（`source`）などを`status_change`として自動記録する（ショートカット経由の「外出中」「在宅」の切り替わりの時間差から、切断が一瞬だったか継続したかを判断できる）。 3. 解析：`/diag/logs?token=…`または`Logs`シートを`at`の新しい順に見る。 4. 掃除：ログは追記のみで溜まり続けるため、`server`フォルダで`npm run clear-logs -- <対象> [--yes]`を実行して消す（対象：`--ios`＝端末IDが`web-`で始まるiPhone（Web版・ショートカット）、`--android`、`--all`、`--member <memberIdの先頭8文字以上>`、`--before <日付>`。複数指定は両方に当てはまるものだけ。`--yes`が無いときは件数の表示のみ。見出し行は消さない）。 5. ローテート保存（v1.4.7以降）：毎日0:00（日本時間）にVercelの定期実行（Cron、`server/vercel.json`）が`GET /cron/rotate-logs`を呼び出し、`Logs`シートのログを、同じスプレッドシートの`log_YYYYMMDD`シート（日付は保存した日。記録時刻の古い順。同じ日の再実行は追記）へ移してから、`Logs`の行を消す（書き込んだ行数を確認できてから、読み取った行だけを消す。実行中に追加されたログは残り、確認できないときは消さない）。同時に、実行日を含む7日より前の`log_YYYYMMDD`シートを削除し、直近7日分だけを残す（例：11/22 0:00に`log_20261122`を作成し`log_20261115`を削除。`Logs`・`Members`・`Groups`など他のシートは対象外）。認証は環境変数`CRON_SECRET`（Vercel Cronの`Authorization: Bearer`）または`DIAG_TOKEN`（手動実行）。`?dryRun=1`で確認のみ。Vercelの無料プランでは実行時刻が0:00〜0:59にずれる。詳細は`API設計書.md`の19を参照 |
| 制約 | iPhoneでは画面が裏に回るとJavaScriptが止まるため、端末側ログは画面を開いたときにまとめて送られる。ログ取得は1.4.5以降の画面を開いた後からで、過去分は遡れない。`DIAG_TOKEN`は推測されにくい値にし、チャット等に貼らず環境変数（Vercel）にだけ設定する。 |

| 入力 | 自動判定の実行（位置の出入り・Wi-Fi接続・約15分ごとの定期確認・アプリを開いたとき）、バックグラウンドタスクのエラー、「Wi-Fiだけで判定する」モード（F27）の切り替え |
| 出力 | `Logs`シートへの追記（`origin="client"`）。`auto_check`（`{trigger, mode, wifi, wifiOn, geo, pos, distM, server, sent, judged, err}`）、`task_error`（`{task, err}`）、`mode_change`（`{wifiOnly}`） |
| 処理内容 | 1. 自動判定が動くたびに、きっかけ（`trigger`：geofence／wifi／periodic／foreground）、判定モード（`mode`：location／wifi_only）、Wi-Fiの分類（`wifi`：home／room／other／unknown／none）とWi-Fiのオン・オフ、ジオフェンスのイベント、現在地の取得結果（`pos`：fresh／lastKnown／none／skipped）と自宅までの距離（`distM`）、サーバー上の状態（`server`）、送信結果（`sent`：ok／same／error）、判定結果（`judged`、判断できなければ`none`）を1件にまとめて端末内（AsyncStorage、最大300件）に貯める。 2. 「状態を送った」「アプリを開いたとき」は即座に、それ以外（判断できなかった・状態が変わらなかった）は、20件以上溜まったか、前回の送信から1時間以上経ったときに`POST /members/:memberId/logs`でまとめて送る（15分ごとの確認のたびに通信しないため）。送れた分だけ端末から消し、送れなかった分は貯めたままにする。 3. ログの記録・送信の失敗は、自動判定そのものを妨げない。 4. 「定期確認が動いていない」「現在地が取れず判断を見送った」などは、`auto_check`が無い・`pos=none`・`judged=none`で後から判別できる |
| 制約 | OSがアプリを止めている間はログも残らない（ログが途切れた時間帯が、動いていなかった時間帯の目安になる）。送信はアプリが動いたとき・通信できるときに限られるため、閲覧時点で最新の分が届いていないことがある |

**サーバー側の自動更新ガード（v1.4.7と同時に反映）**：`PATCH /members/:memberId/status`は、`source="auto"`の更新だけ、重複・誤判定を無視する（同じ状態の再送＝`same_status`、同じ自動更新の5秒以内の重複＝`duplicate`、直前の状態変更から90秒以内の自動「外出」＝`flip_flop`）。無視した場合は状態・通知を変えず`status_ignored`として記録する。「帰宅」と手動操作は無視しない。任意の`trigger`（どの自動化が送ったか）を`status_change`のログに記録する。詳細は`API設計書.md`の「`PATCH /members/:memberId/status`」を参照。

## F27. Wi-Fiだけで判定するモード（アプリ版・Android）

| 項目 | 内容 |
|---|---|
| 概要 | 現在地（位置情報）を使わず、Wi-Fiの接続状況だけで在宅・施設内・外出中を判定するモード。位置情報の取得に失敗して「外出」を送れない（今回の事例：自宅から5km離れても状態が変わらなかった）ことを避け、電池消費も抑える。位置の精度に左右されず、自宅Wi-Fiの有無だけで決まる（v1.4.7） |
| 入力 | 設定画面の「自宅のWi-Fi」欄の「Wi-Fiだけで判定する（位置情報を使わない）」スイッチ（初期値オフ。自宅のWi-Fiが登録済みのときだけ表示・オンにできる） |
| 出力 | 更新後のステータス（F4・F24と同じ経路でサーバーへ送信）、端末ログ（F26。`mode_change`・`auto_check`の`mode=wifi_only`） |
| 処理内容 | 1. オンにすると、位置の見張り（ジオフェンス）を停止し、Wi-Fi接続の見張りと約15分ごとの定期確認だけを動かす。自宅の位置の登録は不要。 2. 判定ルール：(i) 自宅Wi-Fiに接続中→「home」、(ii) 別の部屋のWi-Fiに接続中→「nearby」、(iii) Wi-Fiに接続していない・登録外のWi-Fiに接続中→「away」、(iv) 端末のWi-Fiがオフ・Wi-Fi名が読めない・Wi-Fi未登録→判断材料が無いため状態を変更しない。現在地は取得せず、「別の階・別の部屋を区別する」（厳密モード）の設定にも左右されない。 3. 判定のきっかけは、Wi-Fiへの接続（OSの通知）、約15分ごとの定期確認、アプリを開いたときの3つ。判定結果はサーバー上の状態と比べて、異なる場合だけ送信する（F24と同じ）。 4. オフに戻すと、自宅の位置が登録済みならジオフェンスを再開し、位置も使う判定（F4・F24）に戻る。 5. 自宅のWi-Fiを全て解除したとき、またはグループ退出で参加中のグループが無くなったときは、自動でオフに戻る。設定は端末内にのみ保存する。 |
| 制約 | Android版のみ。Wi-Fiの切断はOSから通知されないため、外出の反映は約15分ごとの定期確認に頼り、最大15分程度（端末の省電力状態によってはそれ以上）遅れる。ごみ出しなどの短い外出は反映されないことがある。Wi-Fiをオフにしている間は判定できず、状態は変わらない（オフにしたまま外出すると、「在宅」のままになる）。モバイル回線だけで位置を使わないため、建物内の別の場所（1Fなど）にいるかどうかは、別の部屋のWi-Fiを登録していない限り見分けられない（自宅Wi-Fiが届かなければ「外出中」になる） |

## F28. 管理者によるメンバーのログ閲覧（アプリ版・Web版）

| 項目 | 内容 |
|---|---|
| 概要 | グループの管理者が、ホーム画面で家族をタップすると、その人のログ（状態の履歴＋技術的なログ）を日付ごとに確認できる。「いつ、どのきっかけで、状態がどう変わったか」「自動判定が動いたのか、何を見て何と判断したのか」を、画面上で調べられるようにして、状態が合わない・記録されないといった不具合の原因調査に使う（v1.4.7） |
| 入力 | ホーム画面（アプリ版）で、管理者が家族の行をタップする操作。Web版は、管理者が家族をタップして開くメニューの「ログを見る」（自分自身の行は、タップでログを直接開く）。表示の切り替え（「すべて」／「状態の変化のみ」） |
| 出力 | ログの一覧画面。日付（日本時間、曜日つき）の見出しの下に、新しい順で「時刻・内容・補足」を並べる。状態の履歴（状態の変化、無視された自動更新とその理由）は目立つ表示、技術的なログ（自動判定の記録、エラー、端末の画面表示・通信の記録など）は控えめな表示にする |
| 処理内容 | 1. 管理者の端末が`GET /members/:memberId/logs`で、対象メンバーのログを取得する（API設計書の20）。 2. サーバーは、現在の`Logs`シートと、ローテート保存済みの`log_YYYYMMDD`シート（直近7日分。F26）の両方から、対象メンバーのログを集め、新しい順（最大1000件）に返す。 3. 画面は各ログを文章にして表示する。`status_change`＝「在宅 → 外出中」＋（自動／手動／管理者による変更、きっかけ、前回の変更からの経過）、`status_ignored`＝「無視：外出中への自動更新」＋理由（すでに同じ状態／直前の重複／直前の変更から90秒以内の外出）、`auto_check`（Android版）＝きっかけ・Wi-Fiの区分・現在地の取得結果と距離・判定・送信結果。それ以外のログはイベント名と内容をそのまま表示する。 4. 「状態の変化のみ」では、状態の履歴だけに絞る。 5. 画面を開いたとき、アプリ版は引っ張って更新できる。Web版は開くたびに取得する。 |
| 制約 | **管理者だけ**が見られる（管理者以外のメンバーには、タップしても何も起きない／サーバーも`403`で拒否する）。端末ID（`device_id`）は本人確認に使う値のため、画面にもAPIの応答にも含めない。参照できる期間はローテートの保存期間と同じ、現在分＋直近7日分。Web版はログの文字列を`textContent`で表示し、ログに含まれる文字列が画面を壊したり実行されたりしないようにする。プライバシーポリシー（F23）に、動作ログの内容と、管理者だけが閲覧できることを記載した |

## F29. 地図の「設定位置」「現在地」ボタンと、「近くにいる」GPS判定のオン／オフ（アプリ版・Android）

| 項目 | 内容 |
|---|---|
| 概要 | 自宅の位置・判定範囲の画面（F3）の地図で、設定した位置と現在地をすぐ見に行けるようにする（「現在地にピンを移動」ボタンも併用できる）。また、マンション内などの「近くにいる」（施設内）をGPSで判定するかどうかを、オン／オフで選べるようにする（v1.4.8） |
| 入力 | 地図上の「設定位置」「現在地」ボタンの操作。「マンション内など『近くにいる』をGPSで判定する」スイッチ（初期値オン。**切り替えた時点で保存・反映される**） |
| 出力 | 地図の中心の移動。保存後は、設定に応じた判定（F4・F24）。設定は端末内にのみ保存する（オフのときだけ印を保存。以前の版・保存が無い端末はオンのまま） |
| 処理内容 | **地図ボタン**：1. 「設定位置」＝ピン（設定した自宅の位置。ピンを動かした後は、動かした位置）を地図の中心にする。ピンが無いときは押せない。 2. 「現在地」＝端末の現在地を取得して地図の中心にする。**ピンは動かさない**。現在地は、地図上の青い点で表示する（位置情報の許可後）。 3. 中心を移すときの拡大率は一定（約1km四方）。画面を開いた直後だけ、最初のピンの位置へ自動で中心を移す。 4. 自宅の位置は、地図のタップ・ピンのドラッグ、または「**現在地にピンを移動**」ボタンで指定する。このボタンは、ピンを現在地へ移し、地図の中心も現在地にする（保存はしない）。v1.4.8で一度廃止したが、現在地へ素早くピンを置く手段として必要なため、v1.4.10で復活した。上の「現在地」ボタン（ピンは動かさず、地図の中心だけを移す）とは別の操作。 5. 設定画面から開いたときのピンの初期位置は、保存済みの自宅の位置（以前は現在地になっていたため修正）。 **「近くにいる」GPS判定**：1. オン（既定）：従来どおり。自宅の半径の外でも施設内の半径の中なら「近くにいる」（F4・F24）。 2. オフ：GPSでは「近くにいる」を作らない。距離が在宅の半径以内なら「在宅」、外側なら「外出中」。施設内の半径のスライダーと円は表示しない（値は保存したまま残し、オンに戻すと復活する）。位置の見張り（ジオフェンス）は、自宅の範囲だけを登録する（建物の範囲は登録しない）。自宅Wi-Fiに未接続のときの「近くにいる」（Wi-Fi名が読めない場合を含む）も使わず、距離だけで決める。 3. **Wi-Fiによる判定は、オフでも変わらない**：自宅Wi-Fiに接続中＝在宅、別の部屋のWi-Fiに接続中＝近くにいる。 4. **スイッチを切り替えた時点で、端末に保存し、ジオフェンスを登録し直して、すぐに判定し直す**（「この位置で保存する」を押さなくても残る。別の画面へ移って戻っても、保存されている設定が表示される。v1.4.9で、以前の「保存ボタンを押したときだけ保存」から変更。自宅の位置が未登録の間は設定だけを保存し、自宅を保存したときにこの設定で見張りを登録する）。半径のスライダーと位置は、従来どおり「この位置で保存する」で保存する。設定画面の「自宅の位置・判定範囲」の行には、オフのとき「施設内のGPS判定：オフ」と表示する。グループ退出で端末のデータを消すときは、オン（初期値）に戻る。 5. 端末ログ（F26）の`auto_check`に、オフのとき`nearbyGps="off"`を記録し、ログ画面（F28）に「近くにいるGPS判定：オフ」と表示する。 |
| 制約 | Android版のみ。オフにすると、自宅の範囲を出た時点で「外出中」になる（半径が小さいと、建物内のGPS誤差で外出中に切り替わりやすい。F3の目安：100〜150m）。Web版（iPhone）には、この設定は無い |
