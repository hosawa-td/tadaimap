# タダイマップ 概要設計書

## 1. システム概要

家族・同居人（2〜4人程度）が、お互いの在宅状況をひと目で確認できるスマートフォンアプリ。スマートフォンの位置情報をもとに、自宅を中心とした範囲（ジオフェンス）に出入りしたタイミングで、「在宅」「施設内（マンション等の同じ建物内の別の場所）」「外出中」の3段階のステータスを自動的に判定する。ステータスは手動でも切り替えられ、在宅中はさらに「トイレ中」等の任意の詳細メモを添えられる。

ネイティブアプリを入れられない端末（主にApple Developer Programに未加入のiPhone）向けに、同じAPIサーバー上でブラウザ用の簡易Web版も提供する。

## 2. 全体アーキテクチャ

```
┌────────────────────┐        ┌──────────────────────┐        ┌───────────────────────┐
│  スマホアプリ         │  HTTPS │  APIサーバー            │        │  Google スプレッドシート │
│  (React Native/Expo) │───────▶│  (Node.js/Express)     │───────▶│  (簡易DB・共有ドライブ)   │
│                      │◀───────│  サービスアカウント経由で │◀───────│                       │
│  ・位置情報の監視       │        │  スプレッドシートを読み書き │        └───────────────────────┘
│  ・在宅/施設内/外出の   │        │  ・招待コードの発行/検証  │
│    自動判定           │        │  ・状態の更新/取得       │        ┌───────────────────────┐
│  ・画面表示            │        │  ・プッシュ通知の送信指示  │───────▶│  Expo Push Notification │
└─────────┬────────────┘        │  ・Web版の配信(静的ファイル)│      │  Service (FCM/APNs仲介)  │
          │                     └──────┬───────────────┘        └───────────────────────┘
          │ 位置情報の取得(OS機能)              │
          ▼                            │ HTTPS(ブラウザから直接)
┌────────────────────┐                 ▼
│ スマホOSの位置情報機能 │        ┌──────────────────────┐        ┌───────────────────────┐
│ (Android/iOS)        │        │  Web版(ブラウザ)         │───────▶│  ブラウザ標準Web Push    │
└────────────────────┘        │  ・vanilla HTML/JS       │◀───────│  (VAPID、iOSはホーム画面 │
                               │  ・Service Worker        │        │  追加時のみ利用可)        │
                               └──────────────────────┘        └───────────────────────┘
```

- アプリ本体はユーザーのスマートフォン上で動作し、自宅の範囲・その一回り外側の範囲（施設内判定用）への出入りをOSの位置情報機能（2重のジオフェンス）で検知する。
- アプリはログイン機能を持たないが、家族間でデータ（状態・招待コード等）を共有するため、間に軽量なAPIサーバーを置く。
- APIサーバーは、サービスアカウントを使ってGoogleスプレッドシートを簡易データベースとして読み書きする。
- 同じAPIサーバーが、静的ファイル配信の仕組み（Express の `express.static`）でブラウザ向けの簡易Web版（`server/public/`）も配信する。ネイティブアプリと同じAPIエンドポイントを叩く。
- 帰宅・外出等のプッシュ通知は、ネイティブアプリ向けにはExpoが提供するPush Notification Service、Web版向けにはブラウザ標準のWeb Push（VAPID）を、それぞれ独立した経路で送信する（どちらか一方が使えなくても、他方や状態更新自体には影響しない）。

## 3. 技術スタック

| 領域 | 採用技術 | 理由 |
|---|---|---|
| モバイルアプリ | React Native + Expo（TypeScript） | 1つのコードでAndroid/iOS両方に対応できるため。位置情報・プッシュ通知のライブラリが標準で揃っている |
| バックグラウンド位置情報 | expo-location, expo-task-manager | アプリを開いていなくても、自宅の範囲への出入りを検知するため |
| プッシュ通知 | Expo Push Notification Service | Android(FCM)/iOS(APNs)の違いを意識せず、共通の仕組みで送信できるため |
| ホーム画面の並び替え(アプリ版) | react-native-draggable-flatlist（react-native-gesture-handler・react-native-reanimatedに依存） | ドラッグ＆ドロップでの並び替えを、定番のジェスチャー処理ライブラリで安定して実現するため。ネイティブコードを含むため、追加時はdev-clientの再ビルドが必要 |
| APIサーバー | Node.js + Express（TypeScript） | 軽量で、Googleスプレッドシートとの連携ライブラリ（googleapis）が扱いやすいため |
| データ保存 | Googleスプレッドシート（共有ドライブ上に配置） | build-kickoffの方針により、簡易データベースとして採用 |
| APIサーバーのデプロイ先 | Vercel（サーバーレス関数として `createApp()` をゼロコンフィグ実行） | 実装完了後にユーザーと相談のうえ決定 |
| Web版（ブラウザ簡易画面） | vanilla HTML/CSS/JS（フレームワーク不使用）+ Service Worker | ネイティブアプリを入れられない端末（主にiPhone）向け。ビルド不要でAPIサーバーから静的配信できるシンプルさを優先 |
| Web版のプッシュ通知 | Web Push API（VAPID鍵、`web-push`ライブラリ） | ブラウザ標準の仕組みのみで、Expoを介さずにWeb版へ通知できるため |

### 3.1 iPhoneのWeb版利用時の制約（重要）

- iOSのSafariでは、**ページを普通のタブで開いているだけではプッシュ通知を受信できない**。一度「ホーム画面に追加」し、そのアイコンから開いた場合のみWeb Pushが有効になる（iOS 16.4以降が必要）。
- Web版はバックグラウンドでの位置情報監視ができないため、自動判定は行わず、手動でのステータス切り替えのみに対応する。

## 4. サービスアカウント利用時の注意点

- サービスアカウント自体には保存容量（マイドライブ）がないため、データ用のGoogleスプレッドシートは必ず**共有ドライブ（Shared Drive）**上に作成する。
- アクセス範囲（スコープ）は、セキュリティを考慮し`drive.file`のような限定スコープではなく、共有ドライブ内の特定スプレッドシートに対する`spreadsheets`スコープを使用する（アプリが新規作成するのではなく、事前に用意した特定のシートを読み書きする設計のため）。

## 5. ディレクトリ構成（実装後）

```
タダイマップ/
├── app/            … React Native (Expo) アプリ本体
└── server/         … APIサーバー (Node.js/Express)
    └── public/     … Web版（ブラウザ簡易画面）の静的ファイル一式
        ├── index.html   … 参加・一覧・状態切替・設定画面（1ファイル構成）
        ├── sw.js        … Web Push受信用 Service Worker
        └── manifest.json, icon.png … ホーム画面追加用
```

## 6. 非機能面の方針

- 実際の位置情報の精度、プッシュ通知の到達性、バッテリー消費などの実機での確認は、実装完了後の簡易テスト、および本格運用前の実機検証で確認する。
- 秘密情報（サービスアカウントの鍵、Web Push用のVAPID秘密鍵など）は`.env`ファイルで管理し、Gitの管理対象外（`.gitignore`）とする。本番環境（Vercel）ではダッシュボードの環境変数機能で設定する。
- プッシュ通知（ネイティブ・Web版どちらも）の送信失敗は、ログに記録するのみとし、状態更新など他の処理を失敗させない方針を徹底する（鍵の設定ミス等が起きても、アプリの基本機能は止まらないようにする）。
