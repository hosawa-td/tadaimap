# デプロイ手順（APIサーバー・Vercel／スマホアプリ・EAS Build）

## 1. APIサーバー（Vercel）

### 事前準備

- `server/src/app.ts` が、Vercelの「Express向けゼロコンフィグ実行」に対応する形で`export default createApp(...)`している（`server/api/index.ts`・`server/vercel.json`は使用しない。過去に作成したが、二重にエントリーポイントを持つと`FUNCTION_INVOCATION_FAILED`になるため削除済み）

### 手順

1. [Vercel](https://vercel.com/)にログインし、「Add New... → Project」からGitHubリポジトリ（`hosawa-td/tadaimap`）をインポートする
2. プロジェクトの設定画面で、**Root Directory を `server` に設定する**（アプリ本体`app/`はデプロイ対象に含めないため）
3. Framework Presetは「Other」のままでよい
4. 「Settings → Environment Variables」に、以下を設定する（`server/.env.example`と同じ内容）
   - `GOOGLE_SHEET_ID`
   - `GOOGLE_SERVICE_ACCOUNT_EMAIL`
   - `GOOGLE_PRIVATE_KEY`（サービスアカウントの秘密鍵。改行は`\n`のまま1行で貼り付ける。**前後に`"`などの引用符を含めない**）
   - `VAPID_PUBLIC_KEY`（Type: Config）／`VAPID_SUBJECT`（Type: Config）／`VAPID_PRIVATE_KEY`（Type: Secret）※Web版のプッシュ通知（Web Push）用。値は`node -e "console.log(JSON.stringify(require('web-push').generateVAPIDKeys()))"`で1回だけ生成する
5. 「Deploy」を押す
6. デプロイ完了後に発行されるURL（例：`https://tadaimap-xxxx.vercel.app`）を、スマホアプリ側の`app/.env`の`EXPO_PUBLIC_API_BASE_URL`、および下記2章のEAS環境変数の両方に設定する

### 注意点

- 環境変数を後から変更・追加した場合、それだけでは反映されない。設定変更後は「Deployments」タブから最新のデプロイを「Redeploy」する
- コード側の修正（`git push`）は自動的に再デプロイされる

### デプロイ結果

- デプロイURL：https://tadaimap.vercel.app
- 実際にGoogleスプレッドシートへの読み書きも含めて動作確認済み（2026-09-18〜）

### トラブルシューティング（発生した事例）

- **`FUNCTION_INVOCATION_FAILED`**：VercelのExpress自動検出が`src/app.ts`をエントリーポイントとして扱うため、同ファイルにdefault exportが必要（対応済み）。
- **`DECODER routines::unsupported`エラー**：`GOOGLE_PRIVATE_KEY`の環境変数の前後に引用符(`"`)が入っていると発生する。値は引用符を含めずに貼り付けること（プログラム側でも自動的に引用符を除去するよう対応済み）。
- **通知処理のエラーが本来無関係な操作（状態更新など）まで失敗させる**：VAPID鍵の設定ミス等で通知送信が例外を投げると、呼び出し元のAPIごと失敗していた。現在はプッシュ通知の送信処理全体をtry/catchで保護し、送信に失敗しても状態更新自体は成功させる方針に修正済み。

## 2. スマホアプリ（Android、EAS Build）

`eas.json`に3つのビルドプロファイルがある。

| プロファイル | 用途 | 特徴 |
|---|---|---|
| `development` | 開発中の動作確認 | dev-client方式。JSはビルドに含めず、実行時にMetro（`npx expo start --dev-client`）から読み込む |
| `preview` | 家族へ配布する正式なビルド（Google Playを使わない直接配布） | JSをビルド時にアプリの中へ埋め込む。以後Metro不要で単体で動く |
| `production` | 将来Google Playストアで公開する場合用 | 現状は`autoIncrement`のみ設定、AAB形式になる想定（未使用） |

### 重要：`EXPO_PUBLIC_*`環境変数はEASの環境変数として登録が必要

`app/src/state/AppContext.tsx`などで使う`process.env.EXPO_PUBLIC_API_BASE_URL`のようなクライアント側の環境変数は、**ローカルの`.env`ファイルには書けるが、それだけではEAS Buildのクラウド側には渡らない**（`.env`はGit管理外＝EAS Buildへのアップロード対象外のため）。

- `development`プロファイルがこれまで正しく動いていたのは、JSをビルドに含めず**ローカルのMetro経由**で読み込んでいたため、ローカルの`.env`がそのまま効いていただけ（cliffのビルド自体には環境変数が渡っていなかった）。
- `preview`/`production`プロファイルは、JSをクラウド側のビルド時に埋め込むため、**EASの環境変数として明示的に登録しないと、コード内のフォールバック値（`http://localhost:3000`）が焼き込まれてしまう**（実際にv1.0.0の初回`preview`ビルドで発生した不具合）。

このため、`EXPO_PUBLIC_API_BASE_URL`・`GOOGLE_MAPS_API_KEY`・`GOOGLE_SERVICES_JSON`は、必ずEASの環境変数として`development`・`preview`・`production`すべてに登録しておく。

```bash
cd app
npx eas-cli env:set --name EXPO_PUBLIC_API_BASE_URL --value "https://tadaimap.vercel.app" \
  --type string --visibility plaintext \
  --environment production --environment preview --environment development --non-interactive

# 登録内容の確認
npx eas-cli env:list --environment preview
```

### ビルド〜配布の手順（Google Playを使わない直接配布）

1. `app/app.config.js`の`version`（例：`1.0.0`）と`android.versionCode`（整数、ビルドごとに必ず増やす）を更新する
2. 上記のEAS環境変数が登録済みであることを確認する
3. ビルドを実行する
   ```bash
   npx eas-cli build --platform android --profile preview --non-interactive
   ```
4. ビルド完了後に表示されるURL（例：`https://expo.dev/accounts/h.osawa/projects/tadaimap/builds/xxxx`）をAndroid端末のブラウザで開き、「インストール」から上書きインストールする
5. 招待コードの発行など、サーバーと通信する操作を実際に試し、本番URL（`https://tadaimap.vercel.app`）に接続できていることを確認する

### リリース履歴

- v1.0.0（`preview`プロファイル、versionCode 2）：Android版の初回正式リリース。versionCode 1のビルドは`EXPO_PUBLIC_API_BASE_URL`未設定によりAPI接続に失敗する不具合があったため破棄。
