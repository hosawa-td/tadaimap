# タダイマップ スプレッドシート設計書（DB設計書）

Googleスプレッドシートを簡易データベースとして使用する。スプレッドシート本体は**共有ドライブ**上に作成し、サービスアカウントに編集者権限を付与する。

ファイル名（案）：`タダイマップ_DB`

## シート一覧

| シート名 | 役割 |
|---|---|
| Groups | 家族グループ、招待コードの管理 |
| Members | グループに参加するメンバー（1人1台のスマホ＝1レコード）の管理 |

## 1. Groups シート

| 列名 | データ型 | 入力規則 | 説明 |
|---|---|---|---|
| group_id | 文字列（UUID） | 必須・一意 | グループの識別子（主キー） |
| invite_code | 文字列（数字6桁） | 必須・一意 | 招待コード |
| invite_code_expires_at | 日時（ISO8601） | 必須 | 招待コードの有効期限（発行から7日後） |
| created_at | 日時（ISO8601） | 必須 | グループ作成日時 |
| nearby_label | 文字列（最大12文字） | 必須・初期値「施設内」 | 「施設内」ステータスの表示名（グループ共通、管理者のみ変更可）。※管理者機能追加前に作成された既存行にはこの列が無いため、読み取り時は空欄を初期値扱いにする（末尾に追加した列） |

## 2. Members シート

| 列名 | データ型 | 入力規則 | 説明 |
|---|---|---|---|
| member_id | 文字列（UUID） | 必須・一意 | メンバーの識別子（主キー） |
| group_id | 文字列（UUID） | 必須（Groups.group_idを参照） | 所属グループ |
| device_id | 文字列 | 必須・一意 | 端末を識別するID（初回起動時にアプリ内で発行し端末に保存） |
| name | 文字列（最大12文字） | 必須 | 表示名 |
| show_name | 真偽値（TRUE/FALSE） | 必須・初期値TRUE | 自分の名前を家族に表示するかどうか |
| status | 文字列（"home" \| "nearby" \| "away"） | 必須・初期値"away" | 在宅／施設内／外出中ステータス |
| status_updated_at | 日時（ISO8601） | 必須 | ステータスの最終更新日時 |
| home_lat | 数値（緯度） | 任意 | 自宅位置の緯度 |
| home_lng | 数値（経度） | 任意 | 自宅位置の経度 |
| home_radius_m | 数値（50〜300） | 任意・初期値100 | 在宅判定の半径（メートル） |
| notify_enabled | 真偽値（TRUE/FALSE） | 必須・初期値TRUE | プッシュ通知を受け取るかどうか |
| push_token | 文字列 | 任意 | Expo Push Notification送信用のトークン（ネイティブアプリ用） |
| created_at | 日時（ISO8601） | 必須 | 参加日時 |
| building_radius_m | 数値（100〜2000、home_radius_m以上） | 任意・初期値300 | 「施設内」判定の半径（メートル）。※末尾に追加した列 |
| nearby_label_unused | ― | ― | 過去の名残の列（個人ごとの呼び方だった時代のもの）。呼び方はGroupsシート側（`nearby_label`）に一本化したため、**現在は使用しない**。列の位置がずれないよう削除せずに残している |
| is_admin | 真偽値（TRUE/FALSE） | 必須・初期値：グループ作成者はTRUE、参加者はFALSE | 管理者かどうか。※末尾に追加した列（管理者機能追加前の既存行はFALSE扱いとなるため、API側で「is_adminの行が1件も無いグループでは、作成日時が最も古いメンバーを管理者とみなす」補完ロジックを持つ） |
| web_push_subscription | 文字列（JSON） | 任意 | Web版のプッシュ通知（Web Push）用の購読情報（`{endpoint, keys:{p256dh, auth}}`をJSON文字列化したもの）。※末尾に追加した列 |
| home_detail | 文字列（最大12文字） | 任意・初期値空文字 | 在宅中の詳細な状態（例：「トイレ中」）。本人のみ設定可。ステータスが変わるたびに自動的に空へ戻す。※末尾に追加した列 |

## シート間の参照関係

- `Members.group_id` は `Groups.group_id` を参照する（多対1）。
- 1つの `group_id` に対し、`Members` は最大4〜5件程度を想定（要件上は2〜4人だが、将来的な余裕を見て運用上の上限は設けない）。
- 1人のユーザー（1台の端末＝1つの `device_id`）が持つ `Members` レコードは常に1件のみ（1グループにしか参加できない制約のため）。

## 運用上の注意

- `invite_code` は同時に有効なものが重複しないよう、発行時にAPIサーバー側でユニークチェックを行う。
- グループの最後のメンバーが退出した場合、`Groups`・`Members`の該当行を削除する（API設計書の退出処理を参照）。
- `Members`シートの列は、機能追加のたびに**末尾へ追加**する方針を取っている（`building_radius_m`以降）。これは、既存行の列位置がずれると過去のデータが誤って読み込まれてしまうため。列を追加する際は、必ずAPIサーバー側の読み込みロジック（列番号ベース）と対応させること。
